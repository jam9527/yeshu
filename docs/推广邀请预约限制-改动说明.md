# 预约权限管控：仅限推广员邀请的用户可预约

## 一、需求背景

目前小程序的预约功能是**完全开放的**——任何进入小程序的用户，只要完成实名认证，就可以直接预约参观。推广员的邀请链接只是用来"记录是谁带来的"，并没有起到"管控入口"的作用。

本次改动的目标是：**关闭自然流量入口，只允许通过推广员分享链接进来的用户进行预约**。换句话说，用户必须先认识一个推广员、拿到邀请链接并点击进入，才能获得预约资格。

---

## 二、改动内容概述

### 改动前（现状）

```
任何用户打开小程序 → 实名认证 → 直接预约 ✅
```

推广链接只是做个"记号"，不限制预约资格。

### 改动后（目标）

```
用户A（自然流量，直接搜索进入）→ 实名认证 → 预约 ❌ 被拒绝
用户B（点了推广员分享的链接进入）→ 实名认证 → 预约 ✅ 正常
```

系统会在用户提交预约时，自动检查"这个用户是不是通过推广员邀请进来的"——不是的话，拒绝预约并提示联系推广员。

---

## 三、具体改动点

### 1. 后端：增加预约准入校验（核心）

**改动位置**：预约提交接口（个人预约 + 团队预约）

**具体逻辑**：
- 用户提交预约时，系统检查该用户是否"被某个推广员邀请过"
- 如果**没有**被邀请记录，且用户本人也不是推广员 → 拒绝预约，返回提示"仅限推广员邀请的用户预约"
- 如果**有**被邀请记录，或用户本人就是推广员 → 正常放行

**该改动的特点**：
- 只加了一道"门禁检查"，不动预约流程本身
- 管理员后台帮用户创建的预约不受影响（走的是另一条通道）
- 不影响现有的推广数据统计

### 2. 小程序端：优化用户提示（配套）

**改动位置**：个人预约页、团队预约页

**具体逻辑**：
- 当后端返回"非邀请用户"的拒绝信息时，前端不显示通用的"请求失败"，而是弹出友好提示框，告知用户需要联系推广员获取邀请链接

**改动前**：用户看到模糊的错误提示，不知道怎么做
**改动后**：用户看到清晰引导，知道要通过推广员邀请才能预约

### 3. 存量用户处理说明

功能上线前已经注册的老用户，如果之前不是通过推广链接进来的，也会受到影响（无法预约）。

**建议处理方式**：
- 这些用户只需要让推广员**重新分享一次链接**，点击进入小程序即可自动获得预约资格
- **不需要重新注册、不需要重新实名认证**，一次点击永久生效
- 这个设计本身也有利于推广员召回老用户，形成二次传播

## 四、不涉及的部分（明确范围边界）

以下内容本次改动**不会动**，避免客户担心影响现有功能：

| 内容 | 是否改动 | 说明 |
|------|----------|------|
| 预约流程本身 | ❌ 不变 | 日期选择、场次选择、信息填写、提交逻辑完全不变 |
| 实名认证 | ❌ 不变 | 认证要求和流程不变 |
| 推广统计数据 | ❌ 不变 | 数据口径、报表展示完全不变 |
| 核销流程 | ❌ 不变 | 到场核销逻辑不受影响 |
| 管理员操作 | ❌ 不变 | 后台帮用户创建/审核预约不受限制 |
| 推广员申请 | ❌ 不变 | 申请成为推广员的流程不变 |
| 团队预约 | ❌ 不变 | 仅增加同样的准入检查，审核流程不变 |

## 五、技术风险与影响评估

| 风险项 | 评估 | 说明 |
|--------|------|------|
| 改动范围 | **低** | 核心改动仅1个后端文件，约6行代码 |
| 对现有用户影响 | **中** | 存量用户需通过推广链接重新进入一次（不丢数据） |
| 系统稳定性 | **低** | 只加校验逻辑，不改核心流程 |
| 性能影响 | **无** | 检查的是用户表已有字段，无额外查询 |
| 可回滚性 | **高** | 去掉校验代码即可恢复原状，无需数据回滚 |

| 测试场景 | 预期结果 |
|----------|----------|

| 推广员分享链接 → 用户点击 → 退出 → 再次进入（不带链接） | ✅ 正常预约（已绑定） |
